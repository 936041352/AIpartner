# 任务

目标对象为动漫/游戏/漫画 XXX 中的 “XXX”，请通过互联网主动研究、整理其背景故事与角色设定。

目标不是撰写人物百科，而是建立适合数字人角色扮演和Chroma检索的角色知识库。

最终输出5个UTF-8纯文本文件：

1. `01_核心历程.txt`
2. `02_补充经历.txt`
3. `03_人物印象.txt`
4. `04_事物认知.txt`
5. `05_角色简述.txt`

前4个文件中的每条记录未来会被单独存入Chroma数据库，因此每条记录必须能够脱离上下文独立理解。

同时维护：

```
00_研究清单_工作文件.txt
```

用于记录研究进度、候选事件、人物、事物、来源、疑点和最终归类。工作文件不属于正式输出。

# 一、研究原则

## 1. 先研究，再总结

不得只根据搜索摘要、单个百科页面或模型已有知识直接生成结果。

先建立目标对象的大致人生时间线、主要剧情阶段、重要人物和重要概念，再针对重要内容继续搜索和核实。

重点搜索：

- 出身与成长经历
- 重要人生转折
- 身份、目标或阵营变化
- 重要关系及关系变化
- 重大成功、失败、创伤或选择
- 重要组织、地点、能力和概念
- 能体现价值观、性格和行为方式的经历与台词
- 当前结局或最新正史状态

对可能进入“核心历程”的事件，应尽量进行单独核查，而不是只依赖角色简介的概括。

## 2. 来源优先级

优先使用：

1. 原作正文、官方剧情、官方网站、官方设定集等直接资料；
2. 能明确对应原作章节、集数、任务或出处的高质量Wiki和资料库；
3. 正规媒体、访谈、攻略和可靠整理文章；
4. 社区讨论只用于发现线索和争议，不单独作为重要事实依据。

搜索结果摘要、AI摘要、无来源角色介绍、同人资料和未经验证的社区说法不得直接作为事实依据。

多个网页重复同一种说法，不等于多个独立来源。

模型自身已有知识只能用于生成搜索线索，不得在没有可靠资料支持时补充正式设定。

## 3. 版本必须统一

如果角色存在原作、动画、游戏、重制版、平行世界或其他版本，必须明确本次研究采用的版本。

禁止把不同设定连续性的经历、关系或能力混合。

用户没有指定时，优先采用主要原作或主要正史版本。

# 二、事实底线

禁止编造资料没有明确支持的：

- 事件
- 时间
- 因果关系
- 动机
- 心理活动
- 人际关系
- 性格特征
- 语言习惯

必须区分：

1. 客观发生的事件；
2. 目标对象自己的认知、记忆和判断；
3. 其他人物的说法；
4. 传闻、梦境、谎言和误解；
5. 网络作者或模型的推断。

研究者知道的真相，不等于目标对象知道。

例如，资料证明某人物实际上是幕后主使，但目标对象本人并不知道，则不得把这一事实写进目标对象对该人物的“人物印象”。

存在不确定性时，应使用：

- “据XXX所知”
- “XXX当时认为”
- “具体时间不详”
- “资料未明确”
- “不同资料存在不同说法”

不得自行补全。

来源冲突时，优先采用更接近原作和官方的资料；仍无法确定时保留冲突，不得擅自选择。

# 三、研究与整理流程

按照以下顺序完成：

1. 确认角色、作品、版本和研究范围。
2. 广泛搜索，建立主要人生阶段、候选事件、人物和事物清单。
3. 对重要事件和存在疑问的内容继续搜索核实。
4. 合并不同网页中实际描述同一事件的信息。
5. 判断事件属于“核心历程”还是“补充经历”。
6. 根据经历整理人物印象和事物认知。
7. 根据前4个文件生成角色简述。
8. 根据研究清单进行一次查漏补缺和事实检查。

当主要人生阶段、重要转折、重要关系和重要认知均已覆盖，继续搜索主要产生重复信息时，可以结束研究。

不要追求穷尽互联网中的所有细节。

# 四、工作文件

`00_研究清单_工作文件.txt`至少记录：

- 研究版本与范围
- 候选事件
- 候选人物
- 候选事物与概念
- 主要来源
- 尚未确认的信息
- 来源冲突或版本问题
- 每项内容最终写入哪个文件
- 已确认、待核实、已排除等状态

重要候选事件建议记录：

【事件】
【时间】
【简述】
【重要性】
【涉及人物】
【来源】
【确认状态】
【计划归类】

工作文件可以包含分析和判断过程，但不要直接复制进正式文件。

# 五、核心历程

文件名：`01_核心历程.txt`

记录塑造目标对象人生轨迹的关键事件。

以下情况通常属于核心历程：

- 改变身份、处境、生活阶段或长期目标；
- 建立、破坏或根本改变重要关系；
- 明显形成或改变价值观、恐惧、执念或行为模式；
- 是多个重要事件的原因或结果；
- 删除该事件后，会使角色人生发展难以理解。

时间不详不影响事件成为核心历程。

每条格式：

```text
【事件】事件名称
【时间】明确时间、大致阶段、相对顺序或“时间不详”
【关键词】关键词1｜关键词2｜关键词3
【内容】事件背景、冲突或选择、目标对象的行动、其他人物回应和结果。
【影响】该事件如何改变目标对象的身份、关系、认知、价值观、目标或行为。
<<<RECORD_END>>>
```

要求：

- 2～5个关键词；
- 同一连续因果事件尽量合并；
- 不按网页段落机械切分；
- 不补写没有依据的动机和结果；
- 每条完整记录不超过500个字符。

# 六、补充经历

文件名：`02_补充经历.txt`

记录不属于人生主干，但有助于理解角色的经历，例如：

- 稳定习惯、偏好、能力或处事方式；
- 有情感意义但没有改变人生方向的事情；
- 小型冲突、日常片段和局部关系事件；
- 能解释某种情绪或行为倾向的具体经历。

不记录普通生活流水账，也不重复核心历程。

格式：

```text
【经历】经历名称
【时间】明确时间、大致阶段、相对顺序或“时间不详”
【关键词】关键词1｜关键词2｜关键词3
【内容】经历背景、目标对象的行动、其他人物回应和结果。
【意义】该经历体现的习惯、偏好、能力、关系特点或情绪倾向。
<<<RECORD_END>>>
```

每条不超过500个字符。

# 七、人物印象

文件名：`03_人物印象.txt`

只整理目标对象真正认识、接触、回忆或明确评价过的重要人物。

重点不是介绍对方，而是：

**目标对象如何理解和对待这个人。**

格式：

```text
【对象】人物名称｜人物类别或身份｜核心关系
【关键词】关键词1｜关键词2｜关键词3
【印象】双方的重要关系经历、关系变化，以及目标对象对其认可、排斥、依赖、恐惧、愧疚、怀疑或在意的部分和典型态度。
<<<RECORD_END>>>
```

要求：

- 只写目标对象知道或认为的内容；
- 不重复完整事件；
- 重大关系变化应体现出来；
- 不确定性必须保留；
- 每条不超过400个字符。

# 八、事物认知

文件名：`04_事物认知.txt`

整理会明显影响目标对象判断、情绪或行为的重要：

- 组织
- 地点
- 物品
- 能力
- 群体
- 制度
- 职业
- 信仰
- 抽象概念
- 道德原则或行为准则

格式：

```text
【对象】名称｜对象类别｜核心特征
【关键词】关键词1｜关键词2｜关键词3
【认知】目标对象认为它是什么、这种认识来自哪些经历，以及目标对象对它的评价和面对它时通常采取的态度或行为。
<<<RECORD_END>>>
```

这里记录的是目标对象的认知，不是客观百科解释。

每条不超过300个字符。

# 九、角色简述

文件名：`05_角色简述.txt`

该文件用于整理角色设定，应优先保留稳定、能够指导角色扮演的信息。AIpartner 不会自动加载 `05_角色简述.txt`；使用者需将其中需要的内容手动整理到角色的 `character_setting.txt`，才会作为角色设定参与对话。

格式：

```text
【背景故事】
不超过400个字符。概括出身、主要成长阶段、关键转折、重要关系变化，以及这些经历如何塑造现在的目标对象。

【性格特质】
世界观、价值观：
对待他人的基本态度：
主要愿望、恐惧与执念：
喜欢、讨厌或无法接受的事物：
自我评价：

性格特质合计不超过300个字符。

【语言与行为风格】
对话风格：
称呼或口癖：
面对亲近者、陌生人、敌人或压力时的典型反应：
标志性话语、台词：

语言与行为风格合计不超过300个字符。
```

无法可靠判断的子项可以省略。

性格结论必须有多个经历、选择、言论或官方描述支持。

不要直接采用“温柔”“冷酷”“傲娇”“偏执”等网络标签，除非资料能够证明这是稳定特征。

语言习惯、口癖和标志性台词必须存在直接依据，不得自行创作。

# 十、统一写作要求

所有正式记录：

- 使用第三人称、简洁准确的陈述句；
- 每条能够脱离上下文独立理解；
- 避免含义不清的“他”“她”“后来”“此事”“对方”等指代；
- 统一人物、地点、组织和事件名称；
- 不进行文学化扩写；
- 不把推断写成事实；
- 不提高原始资料的语义强度。

------

# 十一、完成前必须检查

最终输出前至少检查：

1. 是否混入了不同版本设定；
2. 是否遗漏主要人生转折和重要关系；
3. 核心经历和补充经历是否重复；
4. 是否把角色不知道的事情写成角色认知；
5. 是否把传闻、误解或网络分析写成事实；
6. 是否出现没有可靠来源支持的动机、因果或性格判断；
7. 每条记录是否能够独立理解；
8. 是否符合字符限制；
9. 人物、地点和组织名称是否一致；
10. 前4个文件中的每条记录是否以`<<<RECORD_END>>>`结束；
11. 前4个文件中没有任何规定内容以外的注释。
