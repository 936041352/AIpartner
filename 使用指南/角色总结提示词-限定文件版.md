# 任务（文件优先，可补充外部资料）

本模板采用“文件优先”规则，而非仅使用指定文件：允许使用外部资料补充，出现冲突时以指定文件为准。为保持现有引用不变，仍沿用“限定文件版”的文件名。

请读取指定文件中的全部内容，以文件中的信息为主要依据，整理目标对象“XXX”的背景故事。

你需要输出5个UTF-8编码的正式纯文本文件：

1. `01_核心历程.txt`
2. `02_补充经历.txt`
3. `03_人物印象.txt`
4. `04_事物认知.txt`
5. `05_角色简述.txt`

其中：

- 核心经历用于记录塑造目标对象人生轨迹的关键事件。
- 补充经历用于记录不属于人生主干，但对理解目标对象仍有价值的经历和生活片段。
- 人物印象用于记录目标对象对重要人物的关系认知和情感态度。
- 事物认知用于记录目标对象对重要事物、组织、地点和概念的理解。
- 角色简述用于整理角色设定，需由使用者手动整理到 `character_setting.txt`；AIpartner 不会自动加载 `05_角色简述.txt`。

前4个文件中的每一条记录，未来都会被单独存入Chroma数据库。

将5个正式文件和工作文件保存输入文件所在目录下。

如果输出文件已经存在，先读取现有文件，并询问用户是覆盖、续写还是创建新版本；不得未经确认直接覆盖。

# 工作文件与中间状态

为了避免处理长文时遗漏内容，在生成正式文件前，请先创建并持续维护以下工作文件：

`00_内容清单_工作文件.txt`

该文件是处理过程中的必要中间文件，但不属于5个正式输出文件，不会被放入数字人的系统提示词或Chroma数据库。

工作文件可以包含：

1. 原文文件及章节的读取进度。
2. 候选事件清单。
3. 候选人物清单。
4. 候选事物与概念清单。
5. 人物、地点、组织和事件的统一名称。
6. 原文中的矛盾、疑点和待确认事项。
7. 每个候选内容准备写入哪个正式文件。
8. 已处理、待处理、已排除和需要复查的状态。

候选事件建议记录：

- 临时编号
- 事件名称
- 简短概括
- 大致时间或人生阶段
- 重要性
- 是否影响人生主线
- 涉及人物
- 原文出处
- 计划归类
- 当前处理状态

可以在处理过程中持续更新工作文件。完成5个正式文件后，应使用工作文件进行覆盖检查。

除非用户明确要求，否则不要把工作文件中的分析笔记直接复制到正式输出中。

# 一、事实与推断规则

1. 主要使用所提供文件中的信息，可以搜索互联网信息、作品原设定、模型自身知识或其他文件补充内容，但是出现冲突要以文件中信息为主。
2. 禁止编造原文没有明确支持的事件、时间、因果、动机、心理活动、关系或语言习惯。
3. 必须区分以下内容：
   - 原文明确描述的客观事件；
   - 目标对象自己的认知、记忆或判断；
   - 其他角色的说法；
   - 传闻、猜测、梦境、谎言或可能存在的误解。
4. 对理解角色很重要但存在不确定性的内容，不要直接删除，应使用“据XXX所知”“XXX当时认为”或“原文未明确”等表达保留其不确定性。
5. 如果原文存在矛盾，应保留这种矛盾或标注“原文存在不同说法”，不得自行选择其中一个版本。
6. 可以重新组织和概括原文，但不得改变原意和语义强度。
7. 全部内容使用第三人称、简洁、准确的陈述句。
8. 每一条记录都必须能够脱离上下文独立理解。避免使用含义不明的“他”“她”“此事”“后来”“对方”等指代。
9. 统一同一人物、地点、组织和事件的名称；存在别名时，可以在第一次出现时标注别名。

# 二、长文处理流程

正式生成文件前，请按以下顺序工作：

1. 检查全部输入文件和章节，建立读取进度。
2. 分段阅读全部原文，并持续更新内容清单工作文件。
3. 提取候选事件、人物、事物、概念以及存疑内容。
4. 合并散落在原文不同位置、但实际描述同一事件或对象的信息。
5. 判断每个事件属于“核心历程”还是“补充经历”。
6. 先生成核心历程和补充经历，再生成人物印象与事物认知。
7. 根据前4个文件生成角色简述。
8. 返回原文和工作清单进行覆盖检查，发现遗漏后补充。
9. 最后执行名称一致性、重复内容、事实依据和字数限制检查。

如果一次无法读取全部原文，必须分章节或分段处理，并通过工作文件保存进度。禁止因为上下文长度不足而静默跳过部分内容。

“一个事件”的划分规则如下：

- 围绕同一起因、目标、冲突和结果展开的连续内容，合并为一个事件。
- 出现新的核心冲突、重大选择、关系阶段、生活阶段或明确结果时，可以拆分为新事件。
- 不要按照原文段落机械切分。
- 如果一个事件无法在字数限制内说清楚，可以按因果阶段拆成多个有独立意义的子事件。

# 三、文件1：核心历程

文件名：`01_核心历程.txt`

该文件记录塑造目标对象人生轨迹的关键经历。

核心历程的判断标准：

- 改变了目标对象的身份、处境、生活阶段或长期目标；
- 建立、破坏或根本改变了一段重要关系；
- 形成或改变了目标对象的价值观、恐惧、执念和行为模式；
- 是其他多个重要事件的原因或结果；
- 如果删除这件事，会导致目标对象的人生发展难以理解。

以上标准不是机械打分项，事件至少应满足其中一项。无法明确判断时，优先归入补充经历，并在工作文件中标记为“需要复查”：

事件应尽可能按照发生顺序排列。

如果没有明确日期，可以使用：

- 幼年时期
- 某事件之前或之后
- 加入某组织期间
- 与某人决裂之后
- 具体时间不详

重大事件不能仅仅因为时间不详而被归入补充经历。

每条记录使用以下格式：

```text
【事件】事件名称
【时间】明确时间、大致阶段、相对顺序或“时间不详”
【关键词】关键词1｜关键词2｜关键词3
【内容】事件的背景与起因；目标对象面对的冲突或选择；目标对象采取的行动；其他人物如何回应；最终产生的结果。
【影响】该事件如何改变目标对象的身份、关系、认知、价值观、目标、习惯或情绪反应。
<<<RECORD_END>>>
```

要求：

1. 每个事件提供2～5个有检索意义的关键词。
2. 同一起因、目标、冲突和结果构成的连续因果链，应合并为一个事件。
3. 出现新的重大选择、核心冲突、关系阶段或明确结果时，可以拆分为新事件。
4. 同一事件散落在原文不同位置时，应合并整理。
5. 不得按照原文段落机械切分。
6. 不得为了形成完整故事而补写原文没有提供的动机或结果。
7. 每条完整记录，包括所有标签在内，不超过500个字符。
8. 如果一个重大事件超过限制，应按照因果阶段拆成多个可独立理解的子事件。

# 四、文件2：补充经历

文件名：`02_补充经历.txt`

该文件记录不属于人生主干，但对理解目标对象仍有价值的经历、生活片段和局部事件。

适合收录：

- 展现目标对象稳定习惯、偏好、能力或处事方式的经历；
- 对目标对象有情感意义，但没有改变整体人生方向的事件；
- 比较独立的日常片段、小型冲突或局部关系事件；
- 能够解释目标对象某种情绪或行为倾向的具体经历；
- 发生时间无法确定，而且不属于人生核心转折的事件；
- 不适合并入某个核心事件，但仍值得数字人在对话中回忆的内容。

不应收录：

- 与理解目标对象无关的普通生活流水账；
- 已经完整写入核心历程的同一事件；
- 只能说明某个人物资料，却没有目标对象参与的内容；
- 只有世界观说明、没有具体经历的内容。

每条记录使用以下格式：

```text
【经历】经历名称
【时间】明确时间、大致阶段、相对顺序或“时间不详”
【关键词】关键词1｜关键词2｜关键词3
【内容】这段经历发生的背景；目标对象做了什么；其他人物如何回应；事情最终处于什么状态。
【意义】这段经历体现了目标对象的什么习惯、偏好、能力、关系特点或情绪倾向，以及为什么值得记住。
<<<RECORD_END>>>
```

要求：

1. 每段经历提供2～5个关键词。
2. 每段经历必须具有独立的信息价值。
3. 不要收录对角色塑造没有意义的纯粹流水账。
4. 不要重复核心历程中的完整内容。
5. 如果需要提及核心事件，只能提供理解当前经历所必需的简短背景。
6. 时间不明确时应明确标注，不得猜测具体日期或顺序。
7. 每条完整记录，包括所有标签在内，不超过500个字符。

# 五、文件3：人物印象

文件名：`03_人物印象.txt`

只整理目标对象真正认识、接触、回忆或明确评价过的人物。不要写成该人物的百科介绍，重点是目标对象与其关系及主观印象。

每条记录使用以下格式：

```text
【对象】人物名称｜人物类别或身份｜核心关系
【关键词】关键词1｜关键词2｜关键词3
【印象】目标对象如何认识此人；双方有哪些重要共同经历；关系如何变化；目标对象认可、排斥、依赖、恐惧、愧疚、怀疑或在意对方的哪些部分；面对对方时通常产生什么情绪和行为倾向。必要时说明目标对象对其存在的误解、矛盾感情或例外情况。
<<<RECORD_END>>>
```

要求：

1. 每个人物提供2～5个关键词。
2. 只描述目标对象知道或认为的内容。
3. 如果双方关系在不同时期发生重大变化，应在同一记录中简要交代变化过程；内容过长时可以按关系阶段拆分。
4. 不要重复抄写核心历程或补充经历中的完整事件，只保留解释人物关系和印象所必需的关键经历。
5. 每条完整记录不超过400个字符。
6. 不确定的关系或评价必须保留原文中的不确定性。

# 六、文件4：事物与概念认知

文件名：`04_事物认知.txt`

整理目标对象熟悉或明确评价过的重要事物与概念，包括但不限于：

- 组织
- 地点
- 物品
- 能力
- 种族或群体
- 社会制度
- 职业
- 信仰
- 抽象概念
- 行为准则
- 道德原则

每条记录使用以下格式：

```text
【对象】名称｜对象类别｜核心特征
【关键词】关键词1｜关键词2｜关键词3
【认知】目标对象认为它是什么，这种认识来自什么经历；目标对象对它的感性评价；认可、排斥、依赖、恐惧或怀疑它的哪些部分；面对它时通常采取什么行为。必要时说明这种认知可能存在的错误、偏见、例外或内在矛盾。
<<<RECORD_END>>>
```

要求：

1. 每个对象提供2～5个关键词。
2. 这里记录的是目标对象的认知，不一定等于故事世界中的客观事实。
3. 不要把模型自身对该概念的解释写入结果。
4. 只收录会影响目标对象判断、情绪、关系或行为的重要对象。
5. 每条完整记录不超过300个字符。

# 七、文件5：角色简述

文件名：`05_角色简述.txt`

该文件用于整理角色设定，因此必须简洁、稳定，并优先保留能指导角色扮演的信息。AIpartner 不会自动加载 `05_角色简述.txt`；使用者需将其中需要的内容手动整理到角色的 `character_setting.txt`，才会作为角色设定参与对话。

使用以下格式：

```text
【背景故事】
不超过400个字符。目标对象的出身、主要成长阶段、关键转折、重要关系变化，以及这些经历如何塑造现在的目标对象。

【性格特质】
世界观、价值观：
对待他人的基本态度：
主要愿望、恐惧与执念：
喜欢、讨厌或无法接受的事物：
自我评价：

不超过300个字符。结论必须能够由原文中的经历、选择、言论或明确描述支持，不得只根据单一事件过度概括。

【语言与行为风格】
对话风格：
称呼或口癖：
面对亲近者、陌生人、敌人或压力时的典型反应：
标志性话语、台词：

不超过300个字符。只有原文存在直接对话、行为表现或明确说明时，才能总结具体语言习惯和口癖。原文没有提供的信息填写“原文未明确”，禁止自行创作。
```

某个子条目如果无法根据已有内容判断总结的话可以忽略。

# 八、输出前检查

生成文件前，请逐项检查并自行修正：

1. 是否读取和覆盖了全部原文。
2. 是否遗漏了改变目标对象人生方向的重要事件。
3. 是否将传闻、梦境、谎言或误解写成客观事实。
4. 每条记录是否能够独立理解。
5. 关键词是否具体且适合检索。
6. 是否满足字符上限。
7. 人物印象和事物认知是否只引用必要的事件背景。
8. 是否错误地将重大但时间不详的事件归为补充经历。
9. 补充经历是否具有独立的角色理解价值。
10. 工作清单中的所有候选项目是否均有最终状态。
11. 前4个文件中的每条记录是否都以`<<<RECORD_END>>>`结束。
12. 前4个文件中没有任何规定内容以外的注释。
